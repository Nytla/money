# money.com — проектные решения

Долгоживущий документ: решения, модель данных, объём продукта, статус регламента
тестирования. Планы работ здесь **не** живут — их порождает цепочка скиллов
и складывает в отдельные файлы (карта ниже).

Источники требований: `docs/TZ.txt` (исходник от заказчика),
`docs/testing-cycle.xlsx` (регламент тестирования).
Конвенции кода и команды — в `AGENTS.md`.

## 1. Процесс и терминология

Слово «этап» перегружено — оно означает три разные вещи. Договорённость:

| Термин                    | Что означает                    | Где описано                     |
| ------------------------- | ------------------------------- | ------------------------------- |
| **Фаза A / B / C**        | Порядок работы над продуктом    | пп. 9–11 `TZ.txt`, таблица ниже |
| **Этап N**                | Ступень дорожной карты продукта | раздел 5                        |
| **Проверка N**            | Ступень регламента тестирования | раздел 6, `testing-cycle.xlsx`  |
| **Фаза N** (внутри плана) | Порция работ в `docs/plan-*.md` | вывод скилла `plan-phase`       |

Фазы процесса:

| Фаза                | Содержание                                               | Сдаётся на проверку                           |
| ------------------- | -------------------------------------------------------- | --------------------------------------------- |
| **A. Декомпозиция** | PRD → атомарные задачи → план фаз → issues               | `prd-*.md`, `tasks-*.md`, `plan-*.md`, бэклог |
| **B. Тест-план**    | Тест-кейсы с входами и ожидаемыми результатами           | `test-plan-*.md`                              |
| **C. Разработка**   | Реализация пофазно; тесты пишутся перед кодом своей фазы | рабочий продукт                               |

Исполняемые тесты сознательно **не** пишутся все сразу на фазе B: они писались бы
против несуществующего API и переписывались бы пачками, а красный прогон в течение
недель перестаёт отличать «ещё не сделано» от «сломали работавшее». Гейт при этом
сохраняется полностью — ни строки реализации без утверждённого тест-кейса.

Цепочка скиллов фазы A: `prd` → `decompose` → `plan-phase` → `issues`.
Каждый отвечает ровно за одну операцию: требования, дробление, порядок, выгрузка.

## 2. Принятые решения

| Вопрос          | Решение                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| Тип продукта    | Веб-приложение, личный кабинет (дашборд)                                      |
| Стек            | Next.js 16.3 (App Router, Turbopack), React 19.2, TypeScript, Tailwind CSS v4 |
| Хранилище       | SQLite + Prisma 7; переезд на Postgres — смена `provider`                     |
| Пользователи    | Один (личный сервис), вход по паролю без логина                               |
| Валюта          | Одна на весь учёт, переключатель меняет символ и формат                       |
| Главная таблица | Единый журнал операций: одна строка = одна операция                           |
| Десятина        | Показатель «1/N» = доход ÷ внесённое; целевой процент не задаётся             |
| Состав десятины | Настраиваемый список категорий расхода, по умолчанию «Десятина»               |
| Перенос остатка | Вычисляемая строка на первое число, вне сумм доходов и десятины               |

### Модель главной таблицы

```
Месяц, год   | Дата       | Доход  | Категория | Расход  | Остаток
-------------|------------|--------|-----------|---------|--------
август 2026  | 01.08.2026 | 12 000 | Остаток с прошлого месяца — июля | | 12 000
август 2026  | 01.08.2026 | 90 000 | Зарплата  |         | 102 000
август 2026  | 03.08.2026 |        | Комуналка |   4 500 |  97 500
август 2026  | 05.08.2026 |        | Покупки   |  12 000 |  85 500
август 2026  | 10.08.2026 |        | Десятина  |   9 000 |  76 500
-------------|------------|--------|-----------|---------|--------
ИТОГО        |            | 90 000 |           |  25 500 |  76 500
Десятина, 1/N: 10,0   (доход 90 000 ÷ внесено 9 000)
```

Первая строка — перенос остатка июля. Она **вычисляется при показе**, в базе
не хранится и в итог «Доходы» не входит: иначе остаток июля попал бы в базу расчёта
десятины и был бы обложен ею второй раз. В нарастающий остаток она входит.

Это разрешает противоречие исходного ТЗ, где «Дата Доходов» и «Дата Расходов» стояли
в одной строке: доход и расход — независимые события с разными датами и разным
количеством, их нельзя осмысленно положить в одну строку.

## 3. Модель данных

Одна запись `User` (личный сервис), справочник категорий, журнал операций.
Актуальная схема — `prisma/schema.prisma`, здесь только смысл полей.

```
User
  passwordHash, sessionVersion, currency (ISO 4217), carryOverBalance (false)

Category
  name, kind: INCOME | EXPENSE, iconKey (пресет lucide) | iconData (data URL),
  color, isSystem, sortOrder, countsAsTithe (false)

Transaction
  date (календарный день), kind: INCOME | EXPENSE,
  amountMinor (целое, минорные единицы), categoryId, note
```

Два правила определяют корректность всего расчёта и вынесены в `AGENTS.md`:
деньги — только целые минорные единицы, дата операции — календарный день без времени.

Схема в репозитории пока содержит `User.tithePercent` и не содержит
`Category.countsAsTithe` — приведение к описанному выше входит в задачи T-10 и T-24,
код изменяется на фазе C, не раньше.

### Иконки категорий

Два источника: пресеты `lucide-react` и загрузка своего файла. Загруженная иконка
приводится к квадрату ≤ 128 px и хранится как data URL в БД, а не на диске: при деплое
на serverless записанные на диск файлы не переживают следующий деплой.

## 4. Объём продукта

Что должно существовать в готовом сервисе. Детализация — в PRD, дробление — в задачах.

**`/login`** — форма пароля, ограничение частоты попыток, редирект на `/`.

**`/` — журнал операций**

- Селектор периода: месяц / год / произвольный диапазон.
- Действия слева: «Добавить доход», «Добавить расход», «Добавить категорию».
- Действия справа: валюта, «Выгрузить в Excel», «Сменить пароль», «Выход».
- Таблица со столбцами из раздела 2, нарастающий остаток, строка итогов, блок десятины.
- Редактирование и удаление операции по строке.

**`/stats`** — выбор категории и периода → график. Остаток на конец каждого месяца,
столбцы по категории по месяцам, структура расходов за период.

**`/settings`** — валюта, процент десятины, перенос остатка, смена пароля.

**Аутентификация.** Хеш пароля `bcryptjs`. Сессия — подписанный JWT (`jose`)
в httpOnly + secure + sameSite=lax cookie. Смена пароля требует текущего
и инвалидирует старые сессии через `sessionVersion`.

Проверка двухуровневая. Оптимистичная — в `src/proxy.ts` (в Next.js 16 конвенция
`middleware.ts` объявлена устаревшей и переименована в `proxy.ts`): там доступна
только подпись токена, обращаться к БД нельзя, потому что proxy исполняется вне
рендера и может быть вынесен на CDN. Полная — в `src/lib/auth.ts` рядом с данными:
она же сверяет `sessionVersion` и потому замечает смену пароля.

## 7. Открытые вопросы

1. **Категории доходов.** В ТЗ «Добавить доход» указана дважды (пп. 6 и 9); принято,
   что вторая — «Добавить категорию дохода». Категории заведены и для доходов.
2. **Регулярные операции** (зарплата, коммуналка) — нужен ли шаблон или автоповтор.
3. **Язык интерфейса** — только русский или нужна локализация.

Ни один из оставшихся вопросов не блокирует фазы плана: вопрос 1 принят допущением,
вопросы 2 и 3 относятся к тому, что вынесено за скоуп PRD.

### Закрыто 16.08.2026

- **Формула десятины** — доход ÷ внесённое, столбец «Десятина, 1/N» вместо «Десятина, %».
  Целевой процент не задаётся, `User.tithePercent` удаляется.
- **Состав десятины** — настраиваемый список категорий расхода.
- **Перенос остатка** — нужен, вычисляемой строкой на первое число с заметкой
  «Остаток с прошлого месяца — <месяц>», вне сумм доходов и базы десятины.
