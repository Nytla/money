# Выгрузка плана в GitHub

Последнее звено цепочки: [[prd]] → [[decompose]] → [[plan-phase]] → issues.

Вход: `docs/plan-<фича>.md` (или путь в `$ARGUMENTS`) и файл задач
`docs/tasks-<фича>.md`, на который тот ссылается.
Репозиторий проекта — `Nytla/money`.

## Предварительные условия

Требуется `gh` CLI с выполненной авторизацией: `gh auth status` должен показывать
активный аккаунт. Deploy key репозитория для этого **не годится** — он даёт доступ
только к git-транспорту, но не к GitHub API. Если `gh` не установлен или не
авторизован — остановиться и сказать об этом, а не пытаться обойти.

Перед созданием проверить, что бэклог не заводится повторно:
`gh issue list --state all --limit 200` и список milestones. Совпадения по заголовкам
не дублировать.

## Порядок действий

1. Прочитать план и файл задач.
2. Для каждой фазы создать milestone:
   `gh api repos/:owner/:repo/milestones -f title="Фаза N: название" -f description="цель фазы"`
3. Для каждой задачи фазы создать issue с привязкой к milestone.
4. В конце вывести таблицу: задача → номер issue → milestone.

## Формат issue

**Title** — результат из задачи одной строкой, без префикса `T-NN` и без `[ ]`.

**Body** собирается из полей задачи:

```
Задача: T-<номер> из docs/tasks-<фича>.md

<Зачем — одна фраза>

**Готово, когда:**
- [ ] критерий
- [ ] критерий

**Тест-кейсы:**
- unit: ...
- интеграционный: ...
- e2e: ...

**Зависит от:** #<номера созданных ранее issues> или «ничего»
**Затрагивает:** зоны кода
```

**Метки** по типу задачи: `feature` или `infra`; по зоне: `journal`, `categories`,
`auth`, `export`, `stats`, `db`. Несуществующие метки создавать
через `gh label create` до создания issue, иначе команда упадёт.

## Правила

- Не выдумывать задачи, которых нет в плане, и не менять формулировки критериев:
  issue должна быть дословно проверяема против `docs/tasks-*.md`.
- Зависимости проставлять ссылками на реальные номера issues, поэтому создавать
  их в порядке фаз, а внутри фазы — в порядке зависимостей.
- Если задача зависит от чего-то, чего нет в плане, — остановиться и сообщить,
  это ошибка планирования, а не повод импровизировать.
