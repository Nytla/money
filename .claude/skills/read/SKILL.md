# Экономное чтение файлов

Правило: **никогда не читать файл целиком, если нужна одна функция или модель.**
Сначала найти координаты, потом прочитать узкий диапазон.

Всё делается встроенными инструментами. В этом проекте оболочка — PowerShell,
и unix-команд (`head`, `sed`, `grep`, `jq`, `cat`) здесь нет. Встроенные Read и Grep
не только работают, но и дешевле: Grep — это ripgrep, а Read умеет читать диапазон строк.

## Порядок действий

1. **Найти место.** Grep с `output_mode: "content"` и `-n` даёт номера строк:
   - объявления: `^(export )?(async )?(function|const|class) `
   - модель Prisma: `^model ИмяМодели`
   - ключ в JSON: `"имя_ключа"`

2. **Прочитать только нужное.** Read с `offset` и `limit` — например,
   `offset: 120, limit: 40`. Контекст вокруг совпадения обычно берётся
   через `-C 5` прямо в Grep, без отдельного чтения.

3. **Если файл незнаком** — сначала Read с `limit: 50`, чтобы увидеть импорты
   и структуру, и только потом целиться в нужный участок.

## Частные случаи

**Prisma-схема.** Grep по `^model ` даёт список всех моделей с номерами строк —
дальше читать только нужный блок.

**Сгенерированный клиент** (`src/generated/prisma`) и `package-lock.json` не читать
вообще: тысячи строк без пользы. Нужные типы смотреть в `prisma/schema.prisma`.

**Поиск по всему проекту.** Не перебирать файлы по одному — один Grep с `glob`
(например `**/*.tsx`) заменяет десяток чтений.

## Когда читать целиком

Читать файл целиком уместно, если он короче ~100 строк, если его собираешься
редактировать в нескольких местах, или если это конфиг, где важны все значения.
Экономия не должна превращаться в чтение вслепую.
