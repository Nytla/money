## Инфраструктура

### T-00: Интеграционные тесты работают на изолированной БД

**Тип:** инфраструктурная
**Зачем:** без изолированной базы интеграционные тесты (проверка 3 регламента) либо
портят рабочие данные, либо зависят от порядка выполнения. Разблокирует T-01 и дальше.
**Зависит от:** ничего
**Затрагивает:** тесты, БД

**Готово, когда:**

- [ ] Тесты используют `prisma/test.db`, а не `dev.db`; рабочие данные не меняются при прогоне.
- [ ] Схема на тестовой базе накатывается миграциями, а не синхронизацией схемы.
- [ ] Перед каждым тестом база пуста; упавший тест не влияет на следующий.
- [ ] Фабрики создают пользователя, категорию и операцию с переопределяемыми полями.

**Тест-кейсы:**

- unit: фабрика операции возвращает сумму в минорных единицах
- unit: фабрика даты создаёт календарный день в UTC без времени
- интеграционный: два теста подряд видят пустую базу

## Аутентификация (этап 2)

### T-01: Вход по паролю открывает журнал

**Тип:** пользовательская
**Зачем:** без входа сервис недоступен; это первая сквозная задача через всю систему.
**Зависит от:** T-00
**Затрагивает:** аутентификация
**Источник:** К-02, К-03, К-09

**Готово, когда:**

- [ ] Верный пароль перенаправляет на `/` и создаёт сессию.
- [ ] Неверный пароль показывает одно общее сообщение, не раскрывающее причину.
- [ ] Cookie сессии имеет httpOnly, sameSite=lax и secure вне разработки.
- [ ] Cookie недоступна из JavaScript страницы.
- [ ] Пароль не появляется в логах сервера, адресе страницы и тексте ошибок.

**Тест-кейсы:**

- unit: проверка пароля принимает верный хеш и отвергает неверный
- unit: подписанный токен сессии не проходит проверку после подмены полезной нагрузки
- интеграционный: форма входа с неверным паролем не создаёт cookie
- e2e: вход верным паролем показывает журнал

### T-02: Неавторизованный доступ перенаправляется на вход

**Тип:** пользовательская
**Зачем:** данные учёта не должны открываться по прямой ссылке.
**Зависит от:** T-01
**Затрагивает:** аутентификация
**Источник:** К-01

**Готово, когда:**

- [ ] Запрос любого маршрута кроме `/login` без сессии ведёт на `/login`.
- [ ] Просроченная или подделанная cookie равносильна её отсутствию.
- [ ] Статические ресурсы страницы входа доступны без сессии.

**Тест-кейсы:**

- интеграционный: запрос `/` без cookie отвечает перенаправлением
- интеграционный: запрос `/` с подделанной подписью отвечает перенаправлением
- e2e: прямой переход на `/stats` без входа открывает форму пароля

### T-03: Выход закрывает сессию

**Тип:** пользовательская
**Зачем:** уйти с чужого компьютера, не оставив доступ к учёту.
**Зависит от:** T-02
**Затрагивает:** аутентификация
**Источник:** К-08

**Готово, когда:**

- [ ] «Выход» удаляет cookie сессии.
- [ ] Возврат кнопкой «назад» после выхода показывает `/login`, а не журнал из кеша.

**Тест-кейсы:**

- интеграционный: ответ на выход очищает cookie
- e2e: после выхода переход назад ведёт на форму входа

### T-04: Смена пароля требует текущий

**Тип:** пользовательская
**Зачем:** знание старого пароля — единственная защита от смены злоумышленником.
**Зависит от:** T-01
**Затрагивает:** аутентификация, настройки
**Источник:** К-05, К-06

**Готово, когда:**

- [ ] Смена требует ввода текущего пароля; при неверном — отказ без изменения хеша.
- [ ] Новый пароль короче 8 символов отклоняется с явным сообщением.
- [ ] После успешной смены вход работает новым паролем и не работает старым.

**Тест-кейсы:**

- unit: правило длины пароля отвергает 7 символов и принимает 8
- интеграционный: смена с неверным текущим паролем не меняет хеш в базе
- e2e: смена пароля, выход, вход новым паролем

### T-05: Смена пароля закрывает ранее выданные сессии

**Тип:** пользовательская
**Зачем:** смена пароля должна выбрасывать того, кто уже вошёл со старым.
**Зависит от:** T-04
**Затрагивает:** аутентификация
**Источник:** К-07

**Готово, когда:**

- [ ] Токены, выданные до смены пароля, перестают приниматься.
- [ ] Текущая сессия того, кто менял пароль, остаётся рабочей либо он входит заново — поведение одинаково при каждой смене.

**Тест-кейсы:**

- unit: токен с устаревшей версией сессии не проходит проверку
- интеграционный: запрос со старым токеном после смены пароля отвечает перенаправлением

### T-06: Перебор пароля блокируется

**Тип:** пользовательская
**Зачем:** один короткий пароль без ограничения попыток подбирается за минуты.
**Зависит от:** T-01
**Затрагивает:** аутентификация
**Источник:** К-04

**Готово, когда:**

- [ ] После 5 неудачных попыток подряд вход отклоняется 15 минут даже при верном пароле.
- [ ] Успешный вход обнуляет счётчик попыток.
- [ ] Сообщение о блокировке называет причину и время до разблокировки.

**Тест-кейсы:**

- unit: счётчик попыток блокирует на шестой и разблокирует по истечении окна
- интеграционный: шестая попытка с верным паролем отклоняется
- e2e: пять неверных попыток показывают сообщение о блокировке

## Журнал операций (этап 3)

### T-07: Журнал показывает операции текущего месяца

**Тип:** пользовательская
**Зачем:** главный экран продукта; всё остальное строится вокруг него.
**Зависит от:** T-01
**Затрагивает:** журнал
**Источник:** К-10, К-11, К-12, К-13, К-20

**Готово, когда:**

- [ ] По умолчанию открыт текущий месяц.
- [ ] Столбцы идут в порядке: месяц и год, дата, доход, категория, расход, остаток.
- [ ] Одна строка — одна операция; доход и расход в разных колонках, вторая пуста.
- [ ] Сортировка по дате по возрастанию, при равной дате — по времени создания.
- [ ] Суммы выводятся с разделителями разрядов, двумя знаками и символом валюты из настроек.
- [ ] Даты выводятся как дд.мм.гггг.

**Тест-кейсы:**

- unit: форматирование суммы даёт «90 000,00 ₽» для 9000000 минорных единиц
- unit: форматирование даты даёт «01.08.2026»
- интеграционный: журнал за месяц не показывает операции соседних месяцев
- e2e: после входа видна таблица с ожидаемыми заголовками столбцов

### T-08: В журнале виден нарастающий остаток

**Тип:** пользовательская
**Зачем:** ключевая ценность таблицы — видеть, сколько осталось после каждой операции.
**Зависит от:** T-07
**Затрагивает:** журнал
**Источник:** К-14

**Готово, когда:**

- [ ] Остаток в строке равен остатку предыдущей строки плюс доход минус расход.
- [ ] Первая строка периода стартует от нуля (либо от перенесённого остатка, см. T-25).
- [ ] Остаток корректен при нескольких операциях в один день.

**Тест-кейсы:**

- unit: расчёт остатка на последовательности доход-расход-расход даёт ожидаемый ряд
- unit: остаток не накапливает ошибку округления на 100 операциях по 0,01
- интеграционный: журнал за месяц выводит остаток последней строки, равный итоговому

### T-09: Журнал показывает итоги периода

**Тип:** пользовательская
**Зачем:** ответ на вопрос «сколько всего пришло и ушло» без ручного суммирования.
**Зависит от:** T-08
**Затрагивает:** журнал
**Источник:** К-15

**Готово, когда:**

- [ ] Строка итогов показывает сумму доходов, сумму расходов и конечный остаток.
- [ ] Итоги считаются по всему периоду, а не по видимой части таблицы.
- [ ] Пустой период даёт нули, а не пропуск строки итогов.

**Тест-кейсы:**

- unit: агрегация по периоду возвращает суммы доходов и расходов
- интеграционный: итоги пересчитываются после смены периода

### T-10: Журнал показывает выполнение десятины

**Тип:** пользовательская
**Зачем:** отдельное требование ТЗ — видеть, сколько десятины причитается и внесено.
**Зависит от:** T-09
**Затрагивает:** журнал
**Источник:** К-16

**Готово, когда:**

- [ ] Показана причитающаяся сумма — процент от валового дохода за период.
- [ ] Показана внесённая сумма — расходы по системной категории «Десятина» за период.
- [ ] Показан процент выполнения; при нулевом доходе он равен 100, а не ошибке деления.

**Тест-кейсы:**

- unit: расчёт десятины при доходе 90 000 и взносе 9 000 даёт 100 %
- unit: расчёт десятины при нулевом доходе не делит на ноль
- интеграционный: расход по категории «Десятина» увеличивает внесённую сумму

### T-11: Период переключается на месяц, год или диапазон

**Тип:** пользовательская
**Зачем:** требование ТЗ — смотреть любой месяц или целый год.
**Зависит от:** T-09
**Затрагивает:** журнал
**Источник:** К-17, К-18

**Готово, когда:**

- [ ] Выбираются конкретный месяц, целый год и произвольный диапазон дат.
- [ ] Выбранный период отражён в адресе страницы.
- [ ] Открытие сохранённой ссылки показывает тот же период.
- [ ] Некорректный период в адресе не роняет страницу, а откатывается к текущему месяцу.

**Тест-кейсы:**

- unit: разбор параметров периода из адреса, включая некорректные значения
- unit: границы месяца и года считаются по календарным дням в UTC
- интеграционный: смена периода меняет состав строк и итоги
- e2e: переключение на год показывает операции всех месяцев

### T-12: Пустой период объясняет, что делать

**Тип:** пользовательская
**Зачем:** пустая таблица без объяснения читается как поломка.
**Зависит от:** T-11
**Затрагивает:** журнал
**Источник:** К-19

**Готово, когда:**

- [ ] При отсутствии операций показано объяснение и кнопки добавления дохода и расхода.
- [ ] Строка итогов с нулями при этом остаётся видимой.

**Тест-кейсы:**

- интеграционный: журнал за период без операций рендерит объяснение
- e2e: новый пользователь видит подсказку, а не пустую таблицу

## Операции (этап 4)

### T-13: Доход и расход добавляются из журнала

**Тип:** пользовательская
**Зачем:** без ввода операций таблица бесполезна.
**Зависит от:** T-07
**Затрагивает:** операции, журнал
**Источник:** К-21, К-22, К-23, К-26

**Готово, когда:**

- [ ] Кнопки «Добавить доход» и «Добавить расход» открывают форму с суммой, датой, категорией и заметкой.
- [ ] Список категорий отфильтрован по типу операции.
- [ ] Дата по умолчанию — сегодня, выбирается любая другая.
- [ ] После сохранения строка появляется в журнале без перезагрузки, итоги пересчитаны.
- [ ] Дата сохраняется календарным днём без времени.

**Тест-кейсы:**

- unit: операция, введённая в 02:00 по местному времени, сохраняется тем же календарным днём
- интеграционный: форма дохода не предлагает расходные категории
- e2e: добавление дохода 90 000 показывает строку и меняет остаток

### T-14: Ввод суммы защищён от мусора

**Тип:** пользовательская
**Зачем:** одна принятая некорректная сумма портит весь учёт молча.
**Зависит от:** T-13
**Затрагивает:** операции
**Источник:** К-24, К-25

**Готово, когда:**

- [ ] Принимаются «1 234,56», «1234.56» и «1 234,56» с неразрывным пробелом.
- [ ] Отклоняются буквы, отрицательные значения, ноль и более двух знаков после запятой.
- [ ] Сообщение об отказе называет ожидаемый формат.
- [ ] Сохранённое значение — целое число минорных единиц.

**Тест-кейсы:**

- unit: разбор суммы на наборе корректных и некорректных строк
- unit: округление до копеек происходит ровно один раз
- интеграционный: отправка формы с суммой «abc» не создаёт операцию

### T-15: Операция редактируется

**Тип:** пользовательская
**Зачем:** ошибку ввода нужно исправлять, а не заводить компенсирующую операцию.
**Зависит от:** T-13
**Затрагивает:** операции, журнал
**Источник:** К-27

**Готово, когда:**

- [ ] Из строки журнала открывается форма с текущими значениями.
- [ ] Изменяются сумма, дата, категория и заметка.
- [ ] После сохранения строка и итоги обновлены; при смене даты строка меняет позицию.

**Тест-кейсы:**

- интеграционный: правка суммы меняет итоги периода
- e2e: смена даты операции переносит её в правильное место таблицы

### T-16: Операция удаляется с подтверждением

**Тип:** пользовательская
**Зачем:** удаление необратимо, случайный клик не должен стирать запись.
**Зависит от:** T-13
**Затрагивает:** операции, журнал
**Источник:** К-28

**Готово, когда:**

- [ ] Удаление требует подтверждения; отказ оставляет операцию на месте.
- [ ] После удаления строка исчезает, итоги и остатки пересчитаны.

**Тест-кейсы:**

- интеграционный: удаление операции уменьшает сумму расходов периода
- e2e: отмена подтверждения оставляет строку в таблице

### T-17: Ошибка сохранения не теряет введённое

**Тип:** пользовательская
**Зачем:** повторный набор формы после сбоя — верный способ бросить сервис.
**Зависит от:** T-14
**Затрагивает:** операции
**Источник:** К-29

**Готово, когда:**

- [ ] Показано сообщение, отличающее ошибку проверки от сбоя сохранения.

**Тест-кейсы:**

- интеграционный: при отказе записи в БД форма возвращает введённые значения
- e2e: сообщение об ошибке видно, поля заполнены

## Категории (этап 5)

### T-18: Категория создаётся с иконкой из набора

**Тип:** пользовательская
**Зачем:** требование ТЗ — заводить свои категории расходов.
**Зависит от:** T-13
**Затрагивает:** категории
**Источник:** К-30, К-31, К-33

**Готово, когда:**

- [ ] Форма принимает название, тип (доход или расход) и иконку из пресетов.
- [ ] Название уникально в пределах типа; дубликат отклоняется с сообщением.
- [ ] Созданная категория сразу доступна в формах операций своего типа.

**Тест-кейсы:**

- интеграционный: создание категории с существующим именем и тем же типом отклоняется
- интеграционный: одноимённые категории разных типов создаются обе
- e2e: созданная категория появляется в списке формы расхода

### T-19: Своя иконка загружается файлом

**Тип:** пользовательская
**Зачем:** прямое пожелание ТЗ — «желательно чтобы можно было загрузить иконку».
**Зависит от:** T-18
**Затрагивает:** категории
**Источник:** К-31, К-32

**Готово, когда:**

- [ ] Принимается только изображение размером не больше 1 МБ.
- [ ] Файл другого типа или больше лимита отклоняется с сообщением о причине.
- [ ] Загруженная иконка приводится к квадрату не больше 128 px и переживает перезапуск приложения.

**Тест-кейсы:**

- unit: проверка типа и размера файла на наборе входов
- интеграционный: загруженная иконка читается из базы после пересоздания клиента
- e2e: категория с загруженной иконкой показывает её в журнале

### T-20: Категория переименовывается

**Тип:** пользовательская
**Зачем:** опечатку в названии нельзя исправить пересозданием — на категории висят операции.
**Зависит от:** T-18
**Затрагивает:** категории
**Источник:** К-34

**Готово, когда:**

- [ ] Меняются название и иконка существующей категории.
- [ ] Проверка уникальности имени работает и при переименовании.
- [ ] Операции сохраняют привязку к категории после переименования.

**Тест-кейсы:**

- интеграционный: переименование не разрывает связь с операциями
- интеграционный: переименование в занятое имя того же типа отклоняется

### T-21: Категории защищены от опасного удаления

**Тип:** пользовательская
**Зачем:** удаление используемой категории осиротит операции и сломает итоги.
**Зависит от:** T-18
**Затрагивает:** категории
**Источник:** К-35, К-36

**Готово, когда:**

## Вопросы к PRD

1. **T-05, поведение текущей сессии при смене пароля.** Инвалидировать все сессии
   включая текущую (пользователь входит заново) или сохранить текущую? В PRD
   К-07 говорит только про «ранее выданные». Принято: текущая переиздаётся,
   остальные закрываются.
2. **T-06, где хранить счётчик попыток.** В памяти процесса счётчик обнуляется при
   перезапуске, в БД — переживает. Для однопользовательского локального сервиса
   принято хранение в памяти; если нужен строгий вариант — это меняет объём задачи.
3. **T-19, что делать со старой иконкой** при загрузке новой поверх — заменять молча
   или спрашивать. Принято: заменять.
4. **T-31, вид диаграммы** структуры расходов в PRD не задан. Принято: горизонтальные
   столбцы вместо круговой — доли точнее читаются и лучше работают на узком экране.
5. **T-25 и десятина.** Если остаток переносится, входит ли доход прошлого месяца
   в базу расчёта десятины текущего? Принято: нет, десятина считается только
   от дохода внутри периода.
