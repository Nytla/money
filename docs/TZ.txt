Сервис учёта доходов / расходов на Next.js
1. Вход в систему будет по паролю;
2. Войдя в сервис видим таблицу дохов / расходов за текущий месяц, а над таблицей функционал;
3. Функционал над таблицей это:
 - возможность вывыести любой другой месяц или целый год данных;
 - Кнопка "Добавить доход";
 - Кнопка "Добавить расход";
 - Кнопка "Добавить категорию расхода" - например Покупки, Комуналка, Инвестиции, Благотворительность и т.п. жедательно чтобы можно было загрузить иконку;
 - Кнопка "Добавить доход";
 - с права Кнопка "Выбор валюты";
 - с права кнопка "Выгзузить в Ексель";
 - с права кнопка "Сменить пароль";
 - с права кнопка "Выход";
4. Столбцы у таблицы по порядку:
 - Месяц, год (месяц, гггг);
 - Дата Доходов;
 - Доходы, (тут выбранная валюта);
 - Дата Расходов (дд.мм.гггг);
 - Расходы, (тут выбранная валюта);
 - Остаток, (тут выбранная валюта;
 - Десятина, %;
5. Также можно добавить такую вещь как кнопка "Статистика" в виде графика:
 - статистика по остастку финансов в конце каждого месяца за выбранный период;
 - статистика по инвестициям в каждом месяце за выбранный период;
 - статистика по благотворительности  в каждом месяце за выбранный период;
 - ...
 - суть раздела статистика такова, выбрать Категорию, период и построить наглядную стасистику по данной категории за выбранный период.
6. Проект у нас на Next.js так как проект будем использовать локально можем взять Mysqlite, разработка и тестирование проекта будет в соответствии с файлом testing-cycle.xlsx;
7. Готовым сначала полный план разработки и тестирования проекта, готовим под это модули и скиллы и запускаем работу.
8. Скилы для разработки (факт на 16.08.2026, все установлены):
Цепочка фазы A — prd -> decompose -> plan-phase -> issues:
- prd [Product Requirements Document] - что и зачем
- decompose - дробление на атомарные задачи (свой скилл, написан под проект)
- plan-phase - сборка задач в фазы, порядок и зависимости
- issues [gh CLI] - выгрузка плана в github, требует gh auth login
Разработка и тестирование:
- read - экономное чтение файлов (переписан под PowerShell)
- git-commit - коммиты по Conventional Commits
- test-cycle - прогон регламента testing-cycle.xlsx (свой скилл)
- db-fixtures - изолированная тестовая БД для Prisma (свой скилл)
- vercel-react-best-practices [https://github.com/vercel-labs/agent-skills]
- accelint-react-testing [https://github.com/gohypergiant/agent-skills]
- accelint-ts-testing [https://github.com/gohypergiant/agent-skills]
- playwright-best-practices [https://github.com/currents-dev/playwright-best-practices-skill]
- impeccable [https://github.com/pbakaus/impeccable]

Отклонения от первоначального списка и причины:
- atomic-decomposition - НЕ взят: это скилл для декомпозиции научных статей на
  формулы и код, к продуктовым задачам отношения не имеет. Вместо него написан
  свой скилл decompose.
- accelint-nextjs-best-practices - НЕ взят: на 70% дублирует
  vercel-react-best-practices. Два конкурирующих источника по одному предмету
  хуже одного. Из того же репозитория взяты скиллы тестирования, которых
  не было в списке и которые закрывают проверки 2-3 регламента.
- requesting-code-review (superpowers) - НЕ взят: это плагин-методология из 13
  скиллов, половина дублирует prd и plan-phase, а ревью кода уже есть встроенное
  (/code-review, /security-review).
