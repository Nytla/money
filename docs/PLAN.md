# money.com — уточнённое ТЗ и план разработки

Сервис личного учёта доходов и расходов на Next.js.
Источники: `docs/TZ.txt` (функциональные требования), `docs/testing-cycle.xlsx` (регламент тестирования).

---

## 0. Процесс и терминология

Слово «этап» в проекте перегружено — оно означает три разные вещи. Чтобы не путаться
в обсуждении, договорённость такая:

| Термин             | Что означает                    | Где описано                     |
| ------------------ | ------------------------------- | ------------------------------- |
| **Фаза A / B / C** | Порядок работы над продуктом    | пп. 9–11 `TZ.txt`, таблица ниже |
| **Этап N**         | Этап разработки продукта        | раздел 4 этого файла            |
| **Проверка N**     | Ступень регламента тестирования | раздел 5, `testing-cycle.xlsx`  |

Фазы процесса:

| Фаза                | Содержание                                                           | Сдаётся на проверку                         |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------- |
| **A. Декомпозиция** | PRD → атомарные задачи → план фаз → issues в `Nytla/money`           | `docs/tasks-*.md`, `docs/plan-*.md`, бэклог |
| **B. Тест-план**    | Тест-кейсы с входами и ожидаемыми результатами, привязанные к issues | `docs/test-plan-*.md`                       |
| **C. Разработка**   | Реализация пофазно; исполняемые тесты пишутся перед кодом своей фазы | рабочий продукт                             |

Исполняемые тесты сознательно **не** пишутся все сразу на фазе B: они писались бы
против несуществующего API и переписывались бы пачками, а красный прогон в течение
недель перестаёт отличать «ещё не сделано» от «сломали работавшее». Гейт при этом
сохраняется полностью — ни строки реализации без утверждённого тест-кейса.

Этап 0 (каркас, БД, инструменты, скиллы) выполнен до введения этой схемы,
поэтому декомпозиция фазы A охватывает этапы 2–9.

Цепочка скиллов под фазу A: `prd` → `decompose` → `plan-phase` → `issues`.
Каждый отвечает за одну операцию: требования, дробление, порядок, выгрузка.

## 1. Принятые решения

| Вопрос          | Решение                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------- |
| Тип продукта    | Веб-приложение, личный кабинет (дашборд)                                                 |
| Стек            | Next.js 16.3 (App Router, Turbopack), React 19.2, TypeScript, Tailwind CSS v4            |
| Хранилище       | SQLite + Prisma 7 (файл БД в репозитории-игноре, переезд на Postgres — смена `provider`) |
| Пользователи    | Один (личный сервис), вход по паролю без логина                                          |
| Валюта          | Одна на весь учёт, переключатель меняет символ и формат                                  |
| Главная таблица | Единый журнал операций: одна строка = одна операция                                      |

### Модель главной таблицы

```
Месяц, год   | Дата       | Доход  | Категория | Расход  | Остаток
-------------|------------|--------|-----------|---------|--------
август 2026  | 01.08.2026 | 90 000 | Зарплата  |         | 90 000
август 2026  | 03.08.2026 |        | Комуналка |   4 500 | 85 500
август 2026  | 05.08.2026 |        | Покупки   |  12 000 | 73 500
август 2026  | 10.08.2026 |        | Десятина  |   9 000 | 64 500
-------------|------------|--------|-----------|---------|--------
ИТОГО        |            | 90 000 |           |  25 500 | 64 500
Десятина: 9 000 из 9 000 (100%)
```

Это разрешает противоречие исходного ТЗ, где «Дата Доходов» и «Дата Расходов» стояли
в одной строке: доход и расход — независимые события с разными датами и разным количеством,
их нельзя осмысленно положить в одну строку.

## 2. Модель данных

Одна запись `User` (личный сервис), справочник категорий, журнал операций.

```
User
  id, passwordHash, currency (ISO 4217), tithePercent (default 10),
  carryOverBalance (bool), createdAt, updatedAt

Category
  id, name, kind: INCOME | EXPENSE, iconKey (пресет lucide) | iconData (data URL),
  color, isSystem, sortOrder

Transaction
  id, date (дата операции, без времени), type: INCOME | EXPENSE,
  amountMinor (целое, минорные единицы), categoryId, note, createdAt, updatedAt
```

Два правила, которые определяют корректность всего расчёта:

- **Деньги хранятся целым числом в минорных единицах** (копейки/центы). `Float` для денег даёт
  ошибки округления, которые в таблице учёта видны сразу.
- **Дата операции хранится как календарный день**, без времени и таймзоны. Иначе операция,
  введённая 1 августа в 02:00 по местному времени, уедет в июль при UTC-хранении.

### Иконки категорий

Два источника: набор пресетов (`lucide-react`) и загрузка своего файла. Загруженная иконка
приводится к квадрату ≤ 128 px и хранится как data URL в БД, а не на диске: при деплое на
Vercel/serverless записанные на диск файлы не переживают следующий деплой.

## 3. Экраны и функциональность

**`/login`** — форма пароля, rate-limit на попытки, редирект на `/`.

**`/` — журнал операций**

- Селектор периода: конкретный месяц / целый год / произвольный диапазон.
- Панель действий слева: «Добавить доход», «Добавить расход», «Добавить категорию».
- Панель справа: валюта, «Выгрузить в Excel», «Сменить пароль», «Выход».
- Таблица: столбцы из п. 1, нарастающий остаток, строка итогов, блок «Десятина».
- Редактирование и удаление операции по строке.

**`/stats` — статистика**

- Выбор категории (или «Остаток» как псевдокатегория) и периода → график.
- Линия остатка на конец каждого месяца, столбцы по выбранной категории по месяцам,
  структура расходов по категориям за период.

**`/settings`** — валюта, процент десятины, перенос остатка, смена пароля.

### Аутентификация

Хеш пароля — `bcryptjs`. Сессия — подписанный JWT (`jose`) в httpOnly + secure + sameSite=lax
cookie. Проверка в `middleware.ts` для всех маршрутов, кроме `/login`. «Выход» — сброс cookie.
Смена пароля требует ввода текущего и инвалидирует старые сессии через версию токена.

## 6. Открытые вопросы

1. **Перенос остатка между месяцами.** Остаток считается внутри выбранного месяца
   или переносится с предыдущего? Заложен флаг `carryOverBalance`, по умолчанию выключен.
2. **База для десятины.** 10% от валового дохода за период — принято по умолчанию,
   процент настраивается. Уточнить, считается ли она от дохода или от остатка.
3. **Категории доходов.** В ТЗ кнопка «Добавить доход» указана дважды (пп. 6 и 9);
   принято, что вторая — «Добавить категорию дохода». Категории заведены и для доходов тоже.
4. **Регулярные операции** (зарплата, коммуналка) — нужен ли шаблон/автоповтор.
5. **Язык интерфейса** — только русский или нужна локализация.
