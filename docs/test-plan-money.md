# Тест-план: money.com

**Задачи:** `docs/tasks-money.md`
**План фаз:** `docs/plan-money.md`
**PRD:** `docs/prd-money.md`
**Дата:** 16.08.2026
**Статус:** Draft — на проверку заказчику

104 тест-кейса, сгруппированных по фазам плана. Уровни соответствуют регламенту
`docs/testing-cycle.xlsx`: **М** — модульный (проверка 2), **И** — интеграционный
(проверка 3), **E** — E2E (проверка 4).

Этот документ описывает, **что** проверяется и **какой результат считается верным**.
Исполняемый код тестов пишется на фазе C, перед кодом своей фазы.

---

## Базовые фикстуры

Чтобы входные данные в кейсах не повторялись, определены общие наборы.

**Пользователь П1:** пароль `correct-horse`, валюта `RUB`, перенос остатка выключен.

**Категории:**

| Код    | Название            | Тип    | Признаки                            |
| ------ | ------------------- | ------ | ----------------------------------- |
| К-зп   | Зарплата            | доход  | —                                   |
| К-ком  | Комуналка           | расход | —                                   |
| К-пок  | Покупки             | расход | —                                   |
| К-дес  | Десятина            | расход | системная, засчитывается в десятину |
| К-благ | Благотворительность | расход | —                                   |

**Набор Д1 — август 2026:**

| Дата       | Тип    | Сумма     | Категория |
| ---------- | ------ | --------- | --------- |
| 01.08.2026 | доход  | 90 000,00 | Зарплата  |
| 03.08.2026 | расход | 4 500,00  | Комуналка |
| 05.08.2026 | расход | 12 000,00 | Покупки   |
| 10.08.2026 | расход | 9 000,00  | Десятина  |

Производные: доходы 90 000, расходы 25 500, остаток 64 500, «Десятина, 1/N» = 10,0.

**Набор Д2 — июль 2026** (для проверки переноса):

| Дата       | Тип    | Сумма     | Категория |
| ---------- | ------ | --------- | --------- |
| 01.07.2026 | доход  | 50 000,00 | Зарплата  |
| 20.07.2026 | расход | 38 000,00 | Покупки   |

Производные: остаток июля 12 000.

Суммы в кейсах записаны в рублях для читаемости; в коде они хранятся минорными
единицами (90 000,00 → `9000000`).

## Что тест-план сознательно не покрывает

- **Проверка 5 (производительность и Core Web Vitals)** — измеряется вручную
  на прод-сборке через Lighthouse и анализатор бандла, автотестов не имеет.
- **Проверка 8 (нагрузочное тестирование)** — k6, отдельные сценарии на этапе 9.
  Для однопользовательского локального сервиса нагрузка не является риском.
- **Проверка 9 (UAT)** — ручная приёмка заказчиком по пунктам 1–5 `docs/TZ.txt`.
- **Визуальная регрессия** — скриншотные тесты не заводятся: на проекте нет
  дизайн-макета, с которым можно сверяться, а эталон из собственного вывода
  фиксирует ошибки вместо того, чтобы их ловить.
